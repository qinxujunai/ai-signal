怎么解决

11 类信源进来，一页中文出去。

用固定的流程代替每天手动刷网站：程序收集素材，模型按规则挑选、改写成中文，程序再把链接和数字填回去。

一页读完

先读「30 秒读完」三条，再看头条和要闻，后面是社区、观点、模型、产品、论文、开源和快讯。最新一期约 6 分钟读完。

每条都能回到原文

每条都附原文链接。链接，以及来源标签里的分数、星标、点赞，都由程序按素材编号从原始数据填入，不经过模型。

把边界讲清楚

原文写了限制，就照写；热度只说明有多少人关注，不等于已核实；写错了，就在原期公开更正。

AI 怎么挑

DeepSeek 当主编，规则写进代码里。

每天调用一次模型，返回的内容无法解析时才重试。模型负责挑选、归类、写中文；来源链接和标签里的热度数字由程序填入，模型只能引用编号。

模型
DeepSeek-V4.1-Flash接口名 deepseek-flash
模式
深度思考，JSON 输出
输入
标题、热度和摘要摘要最多 160–420 字，因信源而异；Hacker News 和 Techmeme 只有标题；播客读逐字稿前 9000 字
输出
素材编号和中文文字链接由程序按编号填入
调用
每天 09:35，1 次JSON 无法解析时重试 1 次
用时
32–59 秒deepseek-flash，10 月 26 日至11 月 7 日的 13 次运行

选稿三问

每条素材都要过这三问；没有具体内容，就降级或不选。

  1. 读者会因为这条信息做出不同的决定吗？
  2. 这是新的事实或洞察，还是噪音、情绪、营销？
  3. 有没有具体的东西：数字、版本号、价格、基准分数、名字？

写法也有规定：标题写成一句完整的事实；正文必须带材料里的数字或细节；不写「值得关注」「意义重大」这类空话；材料里的限制条件要保留。模型看到的是标题、热度和摘要，不是全文，所以摘要可能遗漏细节，重要结论请回原文核对。全文见 remix-digest.js。

  1. 程序给每条素材编号

    [H3] (226 分, 265 评论) Anthropic reports $17B in Q3 revenue, commitments of $895B in revised S-1 —— cnbc.com
[T4] Sources: institutional investors told Anthropic that its IPO valuation should be around $1.5T to $1.6T … (Wall Street Journal)

  2. 模型用编号指明出处

    { "ref": "H3", "also": ["T4", "T3"],
  "title": "……", "what": "……" }

  3. 程序按编号填回链接和分数

    标题和正文：模型写的中文

    ●●●  |  Hacker News · 226 分 ›   讨论 ›   Wall Street Journal · Techmeme ›   TechCrunch · Techmeme ›

示意：素材和链接取自 11 月 3 日头条那次真实运行，模型返回的 JSON 做了简化。引用了不存在的编号，这一条直接丢掉；模型不可用时，用原标题排出降级版，并在页脚注明。

技术架构

一个 GitHub 仓库，每天自动跑完全程。

不用自己的服务器。收集、编辑、发送、发布都在 GitHub Actions 里完成，代码全部公开。

  1. 08:10

    闹钟

    前一天发完就给今天定好闹钟，到点启动并认领当天；04:07 起每 20 分钟一次的定时任务作后备。

    relay.js
  2. 09:35

    收集

    并行读取 11 类信源，各取最近的新内容，去掉 60 天内发过的，用时 1–3 秒。

    prepare-digest.js
  3. 09:35

    编辑

    素材编号后交给 DeepSeek，拿回 JSON，再由程序回填链接和数字。

    remix-digest.js
  4. 10:00

    发送

    邮件经 QQ 邮箱 SMTP 发出。

    deliver.js
  5. 10:00

    发布

    更新首页、当期、往期、RSS 和 latest.json，由 GitHub Pages 托管。

    publish.js
准点
计划每天 10:00 发出，可能延迟。截至 11 月 7 日，10 月 23 日起的 16 天里，15 天在 10:00:00 发出；11 月 3 日 GitHub 的定时任务到 10:12 才启动，10:13 才发出。每次运行记录公开可查。
费用
GitHub Actions 和 Pages 对公开仓库免费；模型按 DeepSeek 的用量计费，每天 1 次调用，解析失败时多 1 次。
数据接口
latest.json：当期的期号、标题、三条要点、信源统计和链接。作者的个人主页每天读取它。
源代码
GitHub，MIT 许可，可以自己部署一份。网站不加载外部字体、脚本和统计代码，也不收集邮箱。
