THE PROBLEM

信息太多，判断需要依据。

模型发布、研究进展和社区讨论分散在不同平台。追踪这些消息需要时间；看懂一条新闻，还需要找到它来自哪里、有哪些条件。

01 / 发现

多处线索，一处阅读。

把实验室动态、开发者社区、论文与中文报道放进同一期，集中阅读不同网站的线索。

02 / 理解

先看重点，再读背景。

编辑版通常以简短要点开篇，再展开头条、研究、项目与讨论，帮助建立当天的信息全貌。

03 / 判断

从摘要，回到来源。

正文附来源链接，部分条目也有讨论链接。摘要可能遗漏细节，重要结论需要结合原文判断。

HOW IT WORKS

一份简报，如何产生。

从收集到发布，每一步都能在开源仓库中查看。模型负责组织和摘要，原始材料与程序共同决定可用的信息范围。

  1. 01 · COLLECT

    收集

    读取多类公开信源。新闻主要关注近 36 小时，部分官方博客使用更长时间窗口。

  2. 02 · FILTER

    筛选与编号

    按时间和主题筛选，并尽量过滤近期已发的链接；素材按来源分配编号。

  3. 03 · EDIT

    AI 整理

    调用 DeepSeek 的 deepseek-flash 接口，根据可用素材筛选、归类并生成中文摘要。

  4. 04 · PUBLISH

    生成与发布

    程序回填来源链接与部分指标，生成简报、往期页面和 RSS，由 GitHub Actions 发布。

PROCESS / 处理流程
公开信源→筛选与编号→DeepSeek API→链接回填→GitHub Pages / RSS

部分素材只有标题或短摘要，模型未必读到全文；链接有效不代表内容准确。摘要可能遗漏细节，重要信息请结合原文判断。
